## 目标与推进顺序

在现有二维物理沙盒基础上，让用户拥有明确的挑战目标，能够理解失败原因，并逐步创造有连锁反应的机关。

| 顺序 | 方向             | 首期交付                                   | 用户价值                               |
| ---- | ---------------- | ------------------------------------------ | -------------------------------------- |
| 1    | 挑战模式         | 5 个补画挑战、入杯判定、成功反馈、本地进度 | 从随意尝试变成有目标的反复解题         |
| 2    | 轨迹预览与慢动作 | 实际轨迹显示、慢速播放、暂停单步           | 看懂运动过程，知道下一次该怎么改       |
| 3    | 连锁反应组件     | 先做动态木块，再做铰链与跷跷板             | 从滚动与弹射扩展到推倒、杠杆和机关接力 |

上述首期能力已交付。下一阶段优先补充弹簧与避障挑战、独立失败落点标注，再评估活动物体之间的铰链；以下章节保留完整目标与验收要求，未实现部分仍属于规划。

## 1. 挑战模式

### 玩法与范围

- 每关固定小球、杯子和部分轨道，玩家通过补画轨道完成目标。
- 当前 5 关为第一笔斜坡、向左出发、远处的杯子、精准落杯、接力最后一段。绕过障碍与配合弹簧保留为后续扩展。
- 为关卡配置允许的工具、可编辑对象及画笔笔数上限；首期可使用“最多三笔”的简单约束，按关卡调整。
- 固定对象不能移动、删除或通过 AI 修改；受限工具和补丁提交共用权限校验。
- 显示目标、剩余笔数、重新尝试、重新开始、成功反馈和下一关入口；自由创作保留为独立入口。
- 通关进度保存在本机；首期不依赖账号或在线服务。

### 规则与数据

- 关卡定义包括 ID、版本、标题、说明、初始场景、固定对象 ID、允许工具、绘制预算和目标配置。
- 入杯成功依据目标球进入杯子内腔并持续稳定停留判定，不能仅凭一次接触杯壁判定；停留时长和速度阈值通过固定样例验证后确定。
- 出界或超过关卡模拟时限给出重试提示；暂停时间不计入模拟时限。
- 画一笔消耗一次绘制预算，撤销、重做与擦除后按当前有效的玩家笔迹计算，不能靠拆分或导入绕过限制。
- “重新尝试”保留玩家补画，只重置模拟；“重新开始”恢复关卡初始稿并清空本关补画。
- 挑战草稿、自由创作存档与通关记录分别保存；切换模式不覆盖自由创作内容。

### 验收标准

- 5 关均存在经过验证、满足限制的解法；相同初始条件重复运行可稳定通关。
- 掠过杯口、碰到杯壁或其他球入杯不会误判目标完成。
- 固定对象在拖动、多选、删除、属性修改和 AI 补丁路径下均不可修改。
- 绘制预算、撤销重做、重试与重新开始行为一致；刷新后进度可恢复。
- 试玩观察玩家是否理解目标、能否完成第一关，以及是否主动继续下一关；以结果调整难度和引导。

## 2. 轨迹预览与慢动作

### 第一阶段：实际轨迹与运动观察

- 记录并显示本次模拟中小球实际经过的轨迹，提供显示开关，并区分不同小球。
- 提供 1×、0.5×、0.25× 播放速度；暂停时允许前进一个固定物理步。
- 在失败或出界时保留末端位置，便于定位落点；重置后可编辑设计稿。
- 轨迹采用限频采样和点数上限，避免长时间播放导致内存与绘制开销持续增长。

### 第二阶段：运行前预测

- 使用独立的物理世界和设计稿副本，有限时长地推演预测轨迹。
- 用不同线型区分预测轨迹与实际轨迹，并标示预测范围；预测仅覆盖当前场景和初始条件。
- 设计稿修改后使旧预测失效；重新计算需可取消，并限制计算量。
- 涉及动态木块、铰链或复杂多体碰撞时，先验证预测成本与可信度，再决定支持范围。

### 实现约束与验收

- 慢动作改变单位真实时间内推进的物理步数，不放大或缩小固定物理时间步，不改变重力、弹力和摩擦参数。
- 按相同模拟时间比较时，各播放速度的运动结果应在规定误差内一致，入杯与弹簧触发规则保持一致。
- 暂停单步准确推进一个物理步；继续播放不会重复触发或跳过碰撞。
- 预测计算与轨迹显示不修改设计稿、撤销历史、正式模拟状态及挑战进度。
- 重置清除本轮实际轨迹，设计稿修改清除旧预测；轨迹在达到点数上限后仍可稳定运行。
- 在当前场景容量上限附近复测性能，记录轨迹功能带来的耗时与内存变化。

## 3. 增加能产生连锁反应的组件

### 分阶段组件

| 阶段 | 组件         | 能力与示例                                                 |
| ---- | ------------ | ---------------------------------------------------------- |
| A    | 动态矩形木块 | 可平移、旋转和碰撞；用于多米诺、推动和配重                 |
| B    | 铰链         | 将物体连接到固定支点或另一个物体，限制连接点分离并允许旋转 |
| C    | 跷跷板       | 封装木板与支点，作为一个易放置、易选择的组件，支持杠杆送球 |

先把动态木块的放置、旋转、碰撞与存档做完整，再进入关节系统。跷跷板复用铰链能力，避免维护两套约束逻辑。

### 编辑与物理要求

- 动态木块提供尺寸、旋转角、质量、摩擦与弹性属性，并提供旋转手柄。
- 当前铰链由选中单个木块后的属性按钮添加，入口见 [README](../README.md#给木块添加铰链)，支点显示为圆点。后续可补充独立的连接对象与锚点编辑界面；删除连接对象时，在同一编辑事务中处理关联关节，撤销时一起恢复。
- 跷跷板作为整体选择、移动和删除，内部物理部件不暴露为零散对象。
- 新对象与连接关系纳入结构校验、碰撞预检、撤销重做、存档和导入导出；旧场景仍能读取。
- 明确动态刚体、碰撞体和关节的容量预算，重新评估现有“动态球数量”限制；以实测决定新上限。
- 暂不引入电机、绳索、真实连接弹簧等更多机制，先验证木块与杠杆的玩法收益。

### 验收标准

- 提供“木块接力推球”和“跷跷板送球”两个可重复运行的示例。
- 常用尺寸和质量范围内无明显抖动、关节断裂或物体异常弹飞；高速碰撞和叠放有固定回归场景。
- 重置恢复初始位置、角度与连接关系，运行结果不写回设计稿。
- 整体编辑、删除、撤销重做和存档恢复后，关联对象与关节保持完整。
- 既有小球、轨道、杯子、弹簧场景及挑战判定通过回归验证。
